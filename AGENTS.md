## Project Overview

Eiscue is an on-device agent assistant for iPhone / iPad (app minimum **iOS / iPadOS 26.0**). Task orchestration and tool execution run on the phone; the model is called over a user-configured HTTPS service (OpenAI Chat Completions–compatible, OpenAI Responses, or Anthropic Messages). The agent can optionally observe and operate the device itself.

Main pieces:

- **Eiscue app** (`Apps/Eiscue`, SwiftUI): conversations, model settings (key in Keychain), attachments, on-device dictation, skills, run journal, background execution, device setup UI. `AppModel` (`@MainActor @Observable`) exposes UI projections. `RunCoordinator` / `RunSession` own each execution through durable completion; `DeviceSession` owns connection state and borrowing; `DictationSession` owns recording handoff. `SystemPromptBuilder` supplies versioned instructions; extensions such as `AppModel+Attachments.swift` split it by concern.
- **EiscueAgentKit** (`Sources/EiscueAgentKit`): Eiscue-owned agent/tool/event protocol (`AgentClient`, `AgentEngine`, `AgentTool`, `AgentEvent`), conversation models and `JSONConversationRepository`. `Internal/Runtime` adapts **PiDurableKit** (pinned commit, runs on JavaScriptCore, one SQLite per conversation).
- **Device libraries**: `EiscueDeviceCore` contains `GuardedDevice`, the replaceable `DeviceActuator` and route-setup protocols, injected `DeviceClient`, models, Bluetooth/ReplayKit and Keychain storage. `EiscueDeviceKit` reexports Core and adds the developer-services backend (`LocalDeviceController` → `PhoneAgentNCM` → C ABI → Rust), retaining its default initializers. `EiscueHIDKit` is a Core-only product; its import module is `EiscueDeviceCore`.
- **HID-only app**: `EiscueHID` builds shared app sources with `EISCUE_HID_ONLY`, defaults to ESP32 input, and rejects network routes. It has separate bundle IDs, credential service and App Group (`org.eiscue.hid`, `group.org.eiscue.hid`), its own broadcast extension, and no tunnel extension, NetworkExtension capability or native backend. The full `Eiscue` scheme is unchanged.
- **App extensions**: `Apps/EiscueBroadcast` (ReplayKit broadcast upload; caches only the latest JPEG frame in the App Group) and `Apps/EiscueTunnel` (Packet Tunnel loopback reflector, used only by the local-VPN route). `Apps/Shared` holds config shared by the app and tunnel.
- **Vendor/DeviceBackend**: GPL-3.0 control backend copied from actell at a pinned commit (Swift `PhoneAgentNCM`, C `CNCMBackend`, ObjC `CEiscueAutomation`, Rust crate + vendored `idevice`), shipped as the prebuilt `NCMNativeBackend.xcframework` (arm64 iOS, arm64 simulator, arm64 macOS only; no x86_64).
- **Vendor/LocalTunnel**: LocalDevVPN / StosVPN–derived reflector source and license, bundled as app resources.
- **Firmware** (ESP-IDF v5.5.3): `Passport-BLE` (ESP32-C3 BLE HID), `NCM-Relay` (ESP32-S3 USB NCM relay; bounded USB/CoreDevice and XCTest phone checks passed, broader acceptance open). `Passport-BLE` also builds explicitly for S3: BLE commands with selected BLE or USB HID output, independent ReplayKit observation, no VPN. Its 16 MB profile preserves the attached board's 24 KB NVS layout; do not reuse the C3 partition table. The Wi-Fi hotspot relay has been retired; its design is kept locally in `docs/archive/research/wifi-hotspot-relay-retired.md`. Preserve the existing C3 partition layout and private configuration when updating BLE firmware.
- **C3 companion display**: the existing board profile drives ST7789 with packed Eiscue expressions, localized fixed phases and observed tool-step counts. Optional encrypted AB8/AB9 GATT channels carry only status and the physical OK-stop latch; they are separate from HID commands. A released-then-held OK key unlocks only after disconnect, requiring fresh calibration. S3 has no display channel. Asset sources and generation instructions are in `Firmware/Passport-BLE/Resources/README.md`.

### Change recipes

- **New or changed device tool**: add a `DeviceToolSpec` case and its capability/cost/replay/presentation/image/marker/companion metadata. `DeviceTools.swift` contains exhaustive schema and decision switches; `DeviceTaskRunner` maps app `DeviceTaskAction`s to Core `DeviceAction`s and the same spec. Consumers must use the registry rather than duplicate runtime-name strings. Add a `DeviceCapability` when needed, and advertise it only when the actual actuator supports it and readiness holds. Every action, including Home, app launch, keyboard and text, requires an issued `frameID`; validation limits come from `DeviceInputValidation`. Extend `GuardedDeviceTests` and `DeviceToolSessionTests` / `DeviceTaskRunnerTests` for supported execution, one-use frame authority and unsupported capability filtering.
- **New connection route**: add a `DeviceConnectionMethod` case, implement `DeviceActuator` plus the appropriate `NetworkRouteSetup` or `HIDRouteSetup`, and add the explicit `DeviceClient.connect(method:)` mapping and app selection in `Integrations/DeviceConnection.swift` / `DeviceView`. Setup interfaces have no default unsupported operations or controller downcasts. Inject the setup object explicitly alongside its actuator; a missing interface returns `routeUnsupported`. Routes never fall back to each other. Route changes require an unowned device session and release the old session before replacement. Calibration holds a `.setup` lease through its input task, cancellation/input release and modal dismissal; repeated or stale dismissal must not release a newer owner. A calibration presentation that has not invoked `beginCalibration` must not cancel a retained mapping. Mark invocation before its first suspension, cancel only that presentation's started work once, and await cleanup before releasing its lease.
- **Provider quirk**: keep it inside `Sources/EiscueAgentKit/Internal/Runtime/`, scoped to the exact host/path/protocol like `GoogleCompletionCompatibility`, and cover it with a `ProviderIntegrationTests` URLProtocol fixture.
- **User-visible copy**: edit the String Catalog or Kit `.strings` for both `en` and `zh-Hans`, then search `Tests/` and `UITests/` for the old literal. `DeviceErrorPresentationTests` and several UI tests assert exact text. Keys resolve per table, and a call without `table:` reads `Localizable`; `connection.disconnected` and `run.preparing` exist in both `Localizable` and `Runtime` with different meanings, so check the table before reusing a key. Catalog entries are `manual`, so Xcode does not flag keys that code no longer references.
- **Target, Info.plist, entitlement or localization-list change**: edit `project.yml` and run `xcodegen generate`.

### Architecture rules

- The two Kits **must not depend on each other**. Only the app integration layer bridges them. `DeviceToolSession` (`Apps/Eiscue/Integrations/DeviceTools.swift`) adapts tool schemas/JSON to typed `DeviceDecision`s. `DeviceTaskRunner` depends on DeviceCore only and owns task scope, operation budgets, model-image coordinate projection, timeout gates, redacted logs, progress phases and mandatory post-action observation. Core's `@MainActor GuardedDevice` owns serialization, native-frame grants, age/geometry/liveness checks, shared parameter validation and submitted-outcome classification. Actuators retain only transport-specific conversion and in-flight session/calibration checks; do not add another model-action grant ledger to a route. The visible UIKit calibration field keeps its own single-use target observation and reuses Core's age/liveness predicate; it never authorizes model actions.
- Public Kit APIs must not expose PiDurableKit or actell types. `public` access control defines the API; directories are just organization. There is no separate "Plugin" product.
- Engines are swappable via `AgentClient(engine:)`; device backends via `DeviceClient(actuator:networkSetup:hidSetup:)`. `DeviceController` and its default implementations are removed. New app preferences default to `localVPN` with the developer-services `DeviceClient()`; saved route choices are preserved. Selecting Bluetooth uses `BluetoothDeviceController` and retains the network client for switching back.
- `RunSession` owns the per-run engine, device lease, preparation cancellation, stream state, stop cause and awaited final `RunRecord`. `AppModel` run projections are read-only. `configuredAgent` is separate from executing engines; all clients use the injected `AgentFactory`. Do not release the run or its device lease before engine shutdown, captured-client cleanup and journal persistence finish. Record cleanup failures separately from the work result. Host cleanup policy is route-aware: retain a HID route’s raw unconfirmed result while allowing its local cleanup under host policy; network routes still require confirmed release. Preserve independent sanitized finishTask and fallback disconnect errors. Background execution and notifications use injectable `RunBackgroundExecuting` / `RunNotifying` protocols.
- `DeviceSession` is the sole production writer of client selection, connection status, backend and operation identity. Use its typed connection/setup/release/selection operations and scoped `.run`, `.dictation`, `.repair` or `.setup` lease. Hold setup leases through asynchronous work and cleanup, including canceled pairing and calibration dismissal. Status publication must match the captured identity (client, operation generation and lease); an old completion cannot promote a newer session to ready. DEBUG snapshot seeding is test-only. UI progress flags never grant device authority.
- S3 HID commands and replies use per-connection HMAC and monotonic sequence numbers; every command, including STOP/INFO, is authenticated. First enrollment is restricted to an unclaimed board's first 60 s of power, with the candidate key saved in Keychain before enrollment. Never replace an existing board key automatically. Enrollment uses encrypted Just Works and is a trusted-nearby development flow, without a MITM guarantee.
- The S3 BLE single-button-source change keeps report IDs/handles/widths and the command protocol stable: ABS position report 3 has constant padding, and report 1 supplies buttons. ABS press sends position then DOWN; release sends UP then position. Count actual queued notifications (full ABS 2, partial failure 0/1), retain separate logical ABS watchdog ownership, and keep STOP on raw releases. C3 and USB descriptors remain unchanged. Host fixtures/builds, phone map refresh and one portrait owned-page taps/text/six-probe/zero-model host swipe check passed. Removing the duplicate Button1 source empirically restored contacts in this check; it does not prove iOS internals or broader acceptance.
- Developer control backend (`DeviceControlBackend`) is separate from transport: `automatic` selects XCTest on iOS 26 and CoreDevice DisplayService/HID on iOS 27+; explicit `coreDevice` or `xcTest` is fixed for the session with no fallback. CoreDevice is unavailable below iOS 27. The app picker exposes only the two explicit backends and displays a legacy/default `automatic` preference as its resolved method. Selecting that same effective backend persists the explicit preference without resetting the active or pending session; selecting a different backend releases the current network client before saving, retains pairing, and never connects automatically. An idle client still receives cleanup, without setting the connecting UI state. Do not switch during a run or recovery. The 2026-10-18 iPhone 12 mini checks include an owned-page XCTest full pass, individual CoreDevice full passes with recurring rotation/input failures, and limited zero-model background/stop checks; one real-model Calculator task passed, while broader stability and task coverage remain open. See the dated physical follow-up below. Device-target runpaths must retain `/System/Developer/usr/lib` and `/Developer/usr/lib` for Xcode 27 Testing interop dependencies; never bundle Apple test libraries.
- Connection methods (`DeviceConnectionMethod`): `bluetoothBoard` (BLE HID + ReplayKit; no VPN, pairing file or DDI), `localVPN` (new-install default), `usbBoard` (RemotePairing / CoreDevice paths that need a pairing identity and developer environment). A route never silently falls back to another one. A retired `wirelessBoard` preference loads as disconnected `localVPN` without starting a connection.
- `EiscueBroadcast` compiles `Sources/EiscueDeviceCore/ScreenBroadcast/ScreenBroadcastStore.swift` directly so the extension doesn't link the device backend. Keep that file Foundation-only. Its version-1 latest-frame format remains unchanged: a locked read cache compares `latest.plist` modification time, size and inode before decoding; unchanged geometry checks read no JPEG bytes. Heartbeats and stop requests are still checked on every actual read. Bluetooth's `screenState` / readiness / `cachedStatus` getters perform no file reads; explicit `refreshScreenState`, probe, capture, action and calibration reads run off the main thread. Cached UI activity expires after 3 s without refresh, and protected-data unavailability refuses cached frames. The monitor refreshes screen metadata even while the session is owned, without sending BLE INFO alongside input. The 2026-10-17 offline 34-step fixture (`ScreenBroadcastStoreTests`) measured 68 cached checks in roughly 3–5 ms with zero additional decoded bytes on both toolchains. A separate 26-simulator fixture (`BluetoothScreenStateTests`) published 34 changing 1.49 MB frames: 34 background decodes / 50,674,280 bytes in about 96 ms, zero main-thread decodes and zero file reads from UI getters. These are fixture measurements, not physical ReplayKit or swipe acceptance.
- External Bluetooth events enter `DeviceSession.handle`: authentication and transport loss, ReplayKit activity loss, and changes to session/orientation/dimensions invalidate authority even when idle. `BluetoothSessionEventProjection` ignores frame IDs, timestamps and changing pixels, rebases during owned connection transitions, and leaves the hardware stop to its dedicated callback. The state-machine stop callback closes the tool gate synchronously before awaiting cancellation of the named run.
- Selecting Bluetooth in the full app does not remove the linked GPL backend. Use the `EiscueHID` scheme / `EiscueHIDKit` product for a Core-only build, and run `Scripts/check-hid-boundary.py` against the graph and artifact. Neither build separation nor a symbol audit establishes hardware acceptance or a blanket license/App Store decision.

### Agent / device behavior contracts (do not weaken)

- Task scope is `chat`, `observe`, or `control`, fixed when a run starts. Plain chat registers **no tools** and only a short system prompt. "Allow AI to operate device" defaults on in the device page; explicit off choices persist. New messages use chat scope while the device is unready, and control scope only when allowed and ready. Scope is captured before message persistence and never widened during a run or recovery. Device tools are filtered by the controller's actual `DeviceStatus` capabilities (HID has no Home, app list or bundle-ID launch; restricted keyboard navigation requires supporting firmware plus verified pointer/text calibration, and its visible effect must be checked).
- The runtime always opens with `resume:false`. Recovery is read-only; continuing an interrupted run requires an explicit `.resume`. Unaccepted messages are retried with the same `requestID`.
- Continue using the original scope only when permission still covers it and the device is ready; never widen `observe` to `control`. Missing host records resume as chat with a localized notice. Device continuations across all conversations lock the control toggle. Device runs hold their route through cleanup; plain chat does not prohibit connection changes.
- `AgentToolOutcome`, `AgentPauseReason` and `StopCause` carry execution meaning; do not infer it from translated errors. `AgentToolError.outcomeUnknown` terminates the owning generation before another tool or model request. Interrupted tool results are distinct from ordinary failures. `cancel()` waits for closure and throws on cleanup failure; a failed-close SQLite remains quarantined until process restart. Process-wide runtime ownership prevents two clients opening the same conversation database. `AgentEngineContractTests` cover the real engine and the same contract-checked fake used by App coordinator tests.
- SQLite `acceptedRequestIDs` is authoritative for rebuilding host submission caches in both directions; explicit abandonment remains a separate host decision. `RunJournal` serializes checksummed, numbered append-only deltas and writes a final summary, retaining readable legacy originals. Provider usage is retained once per response as optional input/output/cache-read/cache-write counts, with provider semantics intact; missing fields are not zero and costs are not inferred. Journal deltas and old-record loading retain that distinction. `modelUsageIsComplete` becomes true only after a normal event drain without a stop cause; recovery, interruption and old records with nil remain partial, so a missing response cannot appear complete. Repository loading isolates corrupt conversation records, and unverifiable content blocks garbage collection while healthy records can still save. Existing attachment blobs use digest-name and size checks on save; full content verification belongs to load and collection.
- Normal completion, settled pauses and unused model-request failures retain the selected connection by default after `DeviceClient.finishTask()` releases task-scoped input and invalidates old observations. Bluetooth calibration mismatch during completion clears calibration and requires a new check; it retains BLE and screen sharing and does not fail a completed task. The optional `disconnectAfterTask` setting defaults off. Scene backgrounding alone does not disconnect; plain chat still stops when backgrounded. This is not an execution lease or a guarantee of idle transport survival after OS suspension. Tool-budget and no-progress pauses settle the runtime before retention. Explicit continuation starts a new request and observes again; it never replays settled side effects. Read-only verification tools reserve the final call after an ordinary action. Device action tools use `executionCost=2, verifiesSideEffects=true`: they reserve input plus automatic observation before dispatch, stay unsafe to replay, and return the new screenshot/frame in the same result. Failed post-action observation pauses without repeating the input; storage or delivery uncertainty stops and disconnects. The runner also bounds typed callers with the same per-run operation limit; it does not create another Agent or SQLite loop. Conversation progress is held only from each observation boundary to its action outcome, with callbacks bound to the run ID.
- Side-effect tools use unsafe replay at the runtime level, but the host gate stops after an unknown outcome. `DeviceControlError.deliveryUnknown` is never retried automatically. Only `SubmissionResult.notSubmitted` proves that dispatch did not occur; a thrown error, cancellation or epoch change after dispatch is unknown. `GuardedDevice` releases the connection and blocks further device access after an unknown outcome until an explicit successful connection. Use typed `connectionLost`, `serviceUnavailable`, `capabilityUnavailable` and `routeUnsupported` errors; reserve `unsupported` for unsupported physical-device environments.
- Every action must use the newest screenshot's `frameID` and consumes it; actions, reconnects, rotation or geometry changes invalidate frames. RemotePairing frames last 30 s. ReplayKit stream liveness requires a publication within 3 s, or the extension heartbeat (every 0.5 s) naming the current frame with no newer buffer pending. Per the product decision, new pixels/animation alone do not revoke the model's latest single-use observation: it remains actionable for 30 s from issuance while the stream is live and session/geometry/calibration match. Do not renew that decision age when reading the live stream; paused/stopped sessions never authorize input. `GuardedDevice` issues a new `frameID` for every observation, even when an actuator reuses its source frame. Actuator captures must attach their coordinate-space geometry; screenshots without it are display-only. Coordinates are screenshot pixels.
- Device operations are serialized (concurrent calls return `busy`). Success only means the command was sent; callers re-observe to confirm. `DeviceClient.status()` reads cached readiness without transport commands. Explicit `probe()` refreshes readiness; a failed read-only probe downgrades it without closing the connection. Periodic probes must not race a run, dictation or repair owner. An optional app-list failure retains screen control; genuine transport loss reports `connectionLost`.
- Relative HID swipes use board-timed v1 opcode 10 and the existing relative mouse report; INFO support/readiness bits are separate. Only publish `.swipe` after six setup-only UIKit traces verify actual anchor, one continuous contact, timing, axis/acceleration and pace. Keep the profile scoped to the calibration window/connection/geometry, and plan within its measured range before dispatch. Known failed movement checks retain verified taps/typing; transport or delivery uncertainty still stops. Older firmware never falls back to ABS dragging.
- HID readiness needs three separate conditions: authenticated BLE command connection (S3), selected BLE/USB output ready, and active screen sharing plus four-point touch/text calibration passed. C3 uses the existing encrypted BLE command protocol. A BLE acknowledgement doesn't count as a verified action.
- Stop callbacks carry a `runID` so a stale stop can't cancel a newer run. On event-save failure the host cancels and waits for the engine to close before reopening the same SQLite.
- Background device tasks use `BGContinuedProcessingTask` (`BackgroundExecution.swift`, identifier `$(PRODUCT_BUNDLE_IDENTIFIER).agent.continued-processing`). VPN, ReplayKit and Bluetooth background modes are not execution leases. Agent activity progress retains the user-requested fixed **1,000,000** display scale from launch, with actual completed-step increments and phase text; it is not a workload estimate. Never fabricate heartbeat progress or increment units without completed work. Fill the ring only after successful cleanup and journal persistence, then end the activity. iOS controls dismissal and may end execution early. Apple requires timely real progress ([API](https://developer.apple.com/documentation/backgroundtasks/bgcontinuedprocessingtask), [WWDC25](https://developer.apple.com/videos/play/wwdc2025/227/)); the scale alone is not a proven failure cause. Record expiration callbacks as `StopCause.backgroundExpired`, separate from an App user stop. The callback can also follow system-UI cancellation, so it does not identify a resource cause. Send an enabled local notification only if the activity did not receive the final result, avoiding duplicate alerts.
- Gemini's official OpenAI-compatible endpoint (`GoogleCompletionCompatibility.applies`: HTTPS `generativelanguage.googleapis.com/v1beta/openai`, Chat Completions only) gets `supportsStore=false`, a JS `afterResponse` hook that relabels a tool-bearing `stop` as `toolUse`, and per-call `thought_signature` preservation. Never widen this to other hosts or protocols. A final answer that still carries unexecuted tool calls is an error, never a success.

`.github/workflows/helpers.yml` configures GitHub-hosted Ubuntu for offline Python helper tests on main pushes, pull requests and manual dispatch. Apple gates in `.github/workflows/checks.yml` and `Scripts/run-ci-checks.py` require `vars.EISCUE_APPLE_RUNNERS_ENABLED=true`, registered self-hosted Apple Silicon runners and explicit Xcode 26/27 paths; see `Scripts/ci.md`. The 2026-10-20 read-only GitHub check found zero registered runners; branch protection is not configured. Hosted helpers do not establish an Apple gate.

For more detail, see `docs/architecture/overview.md`, `docs/architecture/agent-kit.md`, `docs/guides/device-setup.md`, `docs/architecture/background.md`, `docs/architecture/local-tunnel.md`, `docs/research/device-control-options.md`, `docs/status/validation.md` (current evidence index; detailed logs in `docs/archive/validation/`) and `docs/status/roadmap.md` (architecture review and plan).

## Build & Commands

Requires an Apple Silicon Mac and Xcode 26+. Validation records use Xcode 26.3 / Swift 6.2.4 and Xcode 27 / Swift 6.4; select one explicitly with `DEVELOPER_DIR`, and give each toolchain its own `swift test --scratch-path` instead of sharing `.build/` products. The Xcode project is generated by **XcodeGen** (`project.yml`, minimum XcodeGen 2.45.0). Regenerate it after any target, settings, Info.plist property or localization-list change; don't hand-edit `Eiscue.xcodeproj`.

Prefer `Scripts/test-swift-package.py --scratch-path <toolchain-specific-path>` with explicit `DEVELOPER_DIR`; it uses a disposable manifest/lockfile copy and never writes the real lockfile or index. Before running SwiftPM directly, preserve the current contents and staged/unstaged state of `Package.resolved`. `swift test` can drop the Xcode-only swift-markdown/cmark pins. Compare with that pre-run state and restore only changes produced by this run; never overwrite pre-existing or concurrent edits with an unconditional checkout/restore from Git.

For logged checks, use `bash Scripts/run-logged-check.sh .build/<unique-name>.log <command> [arguments...]`. It saves stdout/stderr and `exit=<code>`, returns the command's actual exit code, and refuses to overwrite an existing log. Do not end a test wrapper with only `echo`/`printf`: that masks failures as exit 0. A fixture server intentionally stopped after testing is a separate lifecycle result, not a test pass.

```sh
xcodegen generate

# Kit tests (AgentKit + DeviceCore + DeviceKit), no real model
DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer \
python3 Scripts/test-swift-package.py --scratch-path .build/kit-xcode26
# Append --filter ProviderIntegrationTests for local URLProtocol provider checks.

# App build
xcodebuild -project Eiscue.xcodeproj -scheme Eiscue \
  -destination 'generic/platform=iOS Simulator' ARCHS=arm64 build

# HID-only (Core-only) build; then audit it with Scripts/check-hid-boundary.py --app <EiscueHID.app>
xcodebuild -project Eiscue.xcodeproj -scheme EiscueHID \
  -destination 'generic/platform=iOS Simulator' ARCHS=arm64 build

# App unit tests only (fast; no model fixture needed)
xcodebuild -project Eiscue.xcodeproj -scheme Eiscue \
  -destination 'platform=iOS Simulator,id=<SIMULATOR_ID>' -only-testing:EiscueAppTests test

# UI tests that don't need the model fixture
xcodebuild -project Eiscue.xcodeproj -scheme Eiscue \
  -destination 'platform=iOS Simulator,id=<SIMULATOR_ID>' \
  -only-testing:EiscueUITests/EiscueUITests test
```

Device backend (Rust, pinned toolchain 1.96.0; the default rustup toolchain isn't changed):

```sh
rustup toolchain install 1.96.0 --profile minimal --target aarch64-apple-ios,aarch64-apple-ios-sim
bash Scripts/build-device-backend.sh      # rebuilds Vendor/DeviceBackend/Frameworks/NCMNativeBackend.xcframework
CARGO_TARGET_DIR=.build/device-rust rustup run 1.96.0 cargo test --locked \
  --manifest-path Vendor/DeviceBackend/rust/Cargo.toml --lib
bash Scripts/test-owned-automation.sh     # ObjC automation bridge host fixture + iOS SDK syntax checks
```

- Set `CARGO_TARGET_DIR` as above (the build script uses the same directory). Without it Cargo writes an untracked, un-ignored `Vendor/DeviceBackend/rust/target/`.
- The prebuilt xcframework archives are committed in full on each rebuild, so rebuild only when backend source changes, and record the change in the vendor README.
- `build-device-backend.sh` moves the previous xcframework to `.build/previous-NCMNativeBackend-*.xcframework` and needs network access for Cargo.lock dependencies on the first build.
- A full `cargo test` including doctests has 6 known failing vendored `idevice` doctests. Use `--lib` (or `--workspace --features desktop-bootstrap --lib --bins`).
- `Scripts/pair-device-usb.sh --udid '<USB_UDID>' --output .build/pairing/EiscuePairingTransfer.json --enable-wifi` is the desktop USB pairing bootstrap for iOS 26 RemotePairing routes only (see `Scripts/pair-device-usb.md`, `docs/guides/device-setup.md`).
- `python3 Scripts/setup-device.py` is the macOS interactive wrapper. The app's inline connection setup copies a complete command that clones the source into a fresh temporary folder and runs this wrapper, without depending on the user's current directory. The App command passes `--app-pairing-schema 1`; the desktop selects the supported schema intersection and validates before transfer. Keep the v1 JSON/plist format and legacy v1 import compatible, and reject unknown versions before replacing a saved identity. It checks prerequisites, requires explicit USB device selection and confirmation, then generates and transfers an identity to the installed app without overwriting a pending transfer. It cleans up its private desktop temporary files; import remains a user action in the app. It does not prepare DDI, install toolchains, start VPN or run device control. Do not invoke the real pairing flow without user authorization; use `--help` or `Scripts/Tests/test_setup_device.py` for offline verification.

Firmware (ESP-IDF **v5.5.3**; `Scripts/board-idf-env.sh` rejects any other version. `IDF_TOOLS_PATH` is optional). The builds and `test-board-firmware.sh` (which compiles IDF's cJSON) need `IDF_PATH`. The auth host fixture needs clang and OpenSSL; the companion host fixture needs only clang. Neither requires ESP-IDF:

```sh
python3 Scripts/board-firmware.py --help
python3 Scripts/board-firmware.py flash --help
```

Build scripts never open serial ports or flash hardware. The packaging/flashing CLI supports these profiles only:

| CLI profile | Firmware | Board |
| --- | --- | --- |
| `s3-hid` | `Passport-BLE`, BLE commands with selected BLE / USB HID output | ESP32-S3, 16 MB profile |
| `ncm` | `NCM-Relay`, USB NCM relay | ESP32-S3, 4 MB profile |

There is **no C3 BLE CLI profile**; the retired `passport` profile is rejected. C3 BLE build output is an app image. When updating a C3 with the already verified matching partition layout, retain a verified full-flash backup, write only the app partition at `0x20000`, preserve private configuration at `0xF000`, and verify readback. Do not apply this app-only procedure to an unknown layout or write the C3 partition table to S3. See [HID firmware setup](Firmware/Passport-BLE/README.md) for the layout requirements.

For a supported S3 HID or relay package, `board-firmware.py flash` requires both `--port` and `--package`. It checks the package and ROM, backs up and verifies the **entire** flash, then writes and verifies the package images. It never uses `erase_flash` or writes eFuses. This is a package installation path, not the app-only C3 BLE update procedure. Only flash a board, use a serial port, or run on a real device when the user explicitly asks for it.

## Code Style

There are no SwiftLint / SwiftFormat / clang-format configs. Match the surrounding code.

- **Swift 6** language mode with strict concurrency for app and Kits. `PhoneAgentNCM` (vendored) stays in Swift 5 mode. UI state types are `@MainActor`. System/ObjC callbacks that fire on background queues (speech, audio, background tasks) must be non-isolated `@Sendable` closures that hop to `MainActor` explicitly; inheriting MainActor isolation has crashed the app on device before.
- Kit types crossing boundaries are `Sendable`; public enums are `Codable, Sendable` where persisted. Tool parameters use `AgentJSONValue` JSON-schema literals with `"additionalProperties": false`. `mayHaveSideEffects` defaults to `true`; set `false` only for pure observation tools.
- Code is dense: short helpers, several statements per line in places, and few comments. Comments explain *why* a constraint exists (security, race, platform quirk) rather than restating code.
- Every `--…` launch argument must be read only inside `#if DEBUG`. This includes device checks (`--owned-device-check`, `--owned-device-smoke`, `--owned-device-portrait-check`, `--owned-device-background-check`, `--ble-device-check`, `--bluetooth-setup-check`, `--system-pairing-check`, `--loopback-reflector-check`, `--legacy-device-probe`, `--device-connection-check`), tunnel/import helpers (`--import-pairing-transfer`, `--resume-existing-local-tunnel`, `--restart-existing-local-tunnel`), diagnostics (`--pairing-diagnostics`, `--speech-diagnostics`, `--speech-capture-check`, `--bluetooth-stationary-relative-check`), board helpers (`--bluetooth-connect-once`, `--bluetooth-input-bluetooth`, `--ble-usb-input`, `--ble-pointer-coverage-check`), `--pairing-local-interface` (publishes pairing on `en0` instead of the VPN peer) and the `--ui-testing` fixtures. Retired `--wireless-board-probe` / `--owned-device-check-wireless` flags make the setup check return without action. Release builds must not contain automation or auto-import paths. `--owned-device-smoke` requires `--owned-device-check` and limits verification to one connection, screenshot, owned counter-button tap, post-action screenshot and local disconnect; it does not establish cross-app or background acceptance. The portrait subset requires an initially portrait scene and explicitly excludes rotation checks; the background subset additionally excludes focus/text so paste consent does not block independent short-background verification. Neither subset is a full acceptance pass. The diagnostic matches CoreDevice’s fixed display canvas separately from XCTest’s interface-oriented images and waits for actual scene backgrounding after Home.
- `--bluetooth-stationary-relative-check` is opt-in and DEBUG-only. It runs once after the first horizontalSmall probe fails with contactMissing, using the same verified anchor and zero displacement for 192 ms / 12 steps. Record it separately from calibration probes; it is diagnostic only and must not grant swipe capability. New firmware logs are metadata only: HID map read length/fingerprint at most once per connection, and stroke output/mode/handle/report length/subscriptions before DOWN and when the sequence settles (including failures). Never log keys, input/report bytes or change the report map for this diagnostic. On 2026-10-18, S3 BLE completed both moving and stationary commands (ACK14), but all three UIKit observers recorded zero contacts/events. Manual taps/Chinese passed and Done retained sharing/ready/pointer; relative swipe stayed unverified. The stationary comparison is diagnostic evidence only, with no Agent/host run or model call.
- Speech handoff: switching to voice mode or back to keyboard without recording must retain the device connection. For an active iOS 27+ `localVPN` / `usbBoard` connection using CoreDevice DisplayService, an actual tap/hold recording request temporarily releases control after speech/microphone authorization, preserving pairing and VPN. Start capture only after confirmed release; canceled permission/preparation work must never start recording later. After capture finishes, fails or is canceled, or the user switches to keyboard or navigates away, restore the captured route and resolved backend once capture has fully stopped, only in the foreground. The restoration object owns its connection task so backgrounding, loss or operation-ID replacement can still cancel it and clear residual references. Manual connection/backend changes or backgrounding cancel pending restoration; never fall back or retry automatically. Distinguish unconfirmed release from restoration failure in user-facing notices. Failed release prevents recording and must not trigger automatic reconnection; failed reconnection preserves the draft and shows a localized notice. Other routes are unaffected: owned XCTest on any OS, disconnected/merely selected routes, and BLE / USB HID (both use `bluetoothBoard` with ReplayKit, not the `usbBoard` network relay).
- Speech evidence and diagnostics: a three-phase iPhone 12 mini / iOS 27 local-VPN check on 2026-10-15 confirmed nonzero microphone input before CoreDevice connection, all-zero PCM plus system remote-control mute while connected, and restored input after confirmed media release. Pairing and VPN remained unchanged; public `isInputMuted` remained false. This historical check validates capture on that device, not the subsequent automatic voice handoff, transcription or all OS builds. USB network relay uses the same DisplayService backend, but has no microphone acceptance evidence. Unaffected routes still need physical microphone-coexistence acceptance. A stream of all-zero PCM buffers is not evidence of recording. `--speech-diagnostics` and `--speech-capture-check` are DEBUG-only; the latter also requires the former and runs a bounded capture without saving audio or text. Diagnostics store only permissions, audio format, buffer counts, levels and error codes in the app sandbox.
- Post-process orphan recovery is not implemented: the backend currently proves ownership only from the live start reply’s `RemoteSSRC`. Do not persist/reuse that 32-bit token as sufficient cross-process authority or invoke `stopAll`. Recovery first needs verified server-status matching of the caller-generated session/call UUID and durable start/stop bookkeeping.
- Manual connection repair in Settings releases current control while preserving pairing, VPN and conversations. Hold the app's repair gate through microphone teardown; block overlapping runs, connections and route changes. The bounded microphone check requests microphone permission only, never recognizes or saves audio, and cancels when leaving the page or backgrounding. Report connection release separately from nonzero input; an already disconnected client cannot prove that a previous process left no screen session. For unconfirmed results, keep Eiscue foreground and check again; restart only if control is disconnected and microphone input still fails, preserving pairing/VPN. Do not reconnect automatically or claim orphan-session recovery.
- UI elements that tests interact with get stable `accessibilityIdentifier`s (e.g. `sendMessageButton`, `modelSettingsButton`, `deviceNavigationLink`). When you add containers, keep child identifiers reachable; container identifiers have hidden children before. An identifier on a `.accessibilityElement(children: .contain)` container may not be reported with its original element type (sidebar `conversationRow_*` rows are not Buttons); query those with `descendants(matching: .any)`.
- UI follows native iOS 26 Liquid Glass (`.glass` / `.glassProminent` for standalone buttons, semantic backgrounds for content) with a monochrome adaptive accent. See `docs/product/chat-experience.md`.
- Device screen previews and repeat input diagnostics belong to the Debug section for all routes, controlled by the persisted `showsDebugTools` preference (default on in Debug builds). Compile both the setting and diagnostic entries out of Release. Required HID calibration remains visible until valid, independently of the debug preference.
- Message history uses lazy rows and a cached feed projection. Sidebar ordering, pin order and row-menu boundaries share one invalidated projection; do not sort the full history for every menu row. The 2,000-conversation fixture is a host measurement, not device performance. Tool-image previews decode with ImageIO outside MainActor and publish only if the load identity is still current; deletion, clear/cancel and newer results must prevent late publication. Keep initial bottom positioning, respect manual reading while streaming, and freeze asynchronous Markdown publication during device observation/input boundaries. The sidebar opens with a rightward drag and closes leftward; remove its modal surface when fully hidden.
- **Localization**: English is the development language and Simplified Chinese (`zh-Hans`) is the translation. App and extensions use String Catalogs (`Apps/*/Resources/*.xcstrings`, split by area: `Runtime`, `Connections`, `TaskStatus`, `Composer`, `Speech`, `Navigation`, `Bluetooth`, etc.) with `String(localized: "key", table: "Table")`. Kits use `Resources/{en,zh-Hans}.lproj/*.strings` with `String(localized:defaultValue:bundle: .module)`. Use semantic keys, plural variations and Foundation formatting. Never branch on language in Swift. To add a language, update every catalog, add Kit `.lproj` files, add it to `CFBundleLocalizations` in `project.yml`, and regenerate. Model protocols, tool names, bundle IDs and system prompts are not translated. See `docs/product/localization.md`.
- Pass UI keys through `LocalizedStringKey` / `String.LocalizationValue`, or resolve them before passing a `String` to a view; a variable `String` is displayed verbatim. Built-in skill Markdown is canonical English instruction text, with localized names and summaries; its source preview must match the instructions and digest. Imported content remains unchanged.
- Commit messages are short, imperative and sentence case (e.g. "Fix Gemini Chat Completions store compatibility").

- **Kits** (`Tests/EiscueAgentKitTests`, `Tests/EiscueDeviceCoreTests`, `Tests/EiscueDeviceKitTests`) use **Swift Testing** (`import Testing`, `@Suite`, `@Test`, `#expect`, `#require`) and run with `swift test` on macOS. ## Security

- **Secrets**: Model API keys (Keychain service `<bundle identifier>.credentials`: `org.eiscue.app.credentials` or `org.eiscue.hid.credentials`, per-profile accounts `model-profile-<UUID>`; the migrated legacy profile retains `model-key`) and RemotePairing private keys (`KeychainPairingIdentityStore`) use `kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly` Keychain items. They must never go to UserDefaults, logs, chat, run reports, or files. `ModelSettings` deliberately excludes credentials.
- **Model endpoints**: The app accepts only HTTPS base URLs without userinfo, query or fragment. Loopback HTTP is allowed only in DEBUG with `--ui-testing` and an `EISCUE_TEST_MODEL_URL` on `127.0.0.1`. The model fixture must never echo request credentials.
- **Screen data**: Device tools send screenshots to the configured model both for explicit observation and for automatic post-action observation. Starting screen sharing or opening a manual preview does not by itself send frames to the model. The broadcast extension stores only the latest JPEG (longest side ≤ 1600 px) in the file-protected App Group container, with no video history and no audio. Requests keep the two newest device-tool images via `DeviceImageContext`; user images, tool-call correlations and opaque provider signatures are preserved. This only trims requests. Tool results pass through the durable runtime, whose per-conversation SQLite history may contain image data; do not claim screenshots are never written to disk. Treat runtime databases as sensitive screen history, separate from the redacted run reports below.
- **Text input** uses a redacted native Unicode event for owned XCTest, without accessing the clipboard. Its receipt deadline is 15 seconds plus one second per started 60 UTF-8 bytes (at most 152 seconds); Home/touch retain 15 seconds and the run's overall deadline still applies. CoreDevice and ESP32 HID overwrite the system clipboard and paste, without reading its previous contents. A receipt never proves visible input; re-observe and never retry an unknown outcome.
- **Reports/logs**: Exported run reports include only allowed metadata and tool status. They never include keys, pairing data, raw screenshots, or full input arguments. Device OSLog (`org.eiscue.device`/`connection`) records only operation names and numeric codes. Rust `tracing` is compiled with `max_level_off` so protocol traces can't leak credentials or frames.
- **Pairing transfer**: `EiscuePairingTransfer.json` (gitignored, mode `0600`) contains a private key. The app deletes it after import, and the desktop copy should be removed. Never commit it or put it in chat or cloud storage. The iOS UI-automation passcode is entered by the user on the device only.
- **Never commit**: `.build/` contents such as board flash backups (`.build/board-backups/`, which can contain device identity), `wifi-setup.txt` SSID/password, raw device logs, crash reports, passcode-page screenshots, or pairing files. PEM files under `Vendor/DeviceBackend/rust/tests/fixtures/lockdown/` are test fixtures only.
- **Skills**: Imported skills are UTF-8 Markdown instructions only. Scripts inside them are never executed, and skills can't widen tool permissions or grant a shell.
- **Attachments** are copied to app-private storage, re-encoded to strip EXIF, and bounded (max 4 per message, 20 MiB source, 2048 px / 2 MiB images, 100-page PDFs, 60,000 bytes of extracted text). They're sent to the model only on send.
- **Licensing**: The linked device backend is GPL-3.0-only (vendored `idevice` is MIT), the tunnel uses the custom StosVPN license, and PiDurableKit is CC0 plus embedded JS notices. Original HID application source in `Firmware/Passport-BLE` is Apache-2.0; the relay firmware retains its GPL license and provenance. Neither statement grants rights to the app / companion artwork or replaces third-party component licenses. Artwork provenance is recorded in [the companion resources README](Firmware/Passport-BLE/Resources/README.md), which makes no licensing claim for it. Keep provenance files (`SOURCE_MANIFEST.json`, `UPSTREAM_THIRD_PARTY.md`, `LICENSE`, `DEVICE_HUB_LICENSE`) in place and record upstream-file changes in the manifest. Don't make or imply a license decision for all of Eiscue. The developer-services route relies on private DDI interfaces and has no App Store commitment.

## Configuration

- **Project settings** live in `project.yml`: iOS deployment target 26.0, `SWIFT_VERSION` 6.0, `SWIFT_EMIT_LOC_STRINGS`, automatic signing with `DEVELOPMENT_TEAM` Q2T8TN4ZW6. Bundle IDs are `org.eiscue.app` (app), `.tunnel`, `.broadcast`, `.tests` and `.uitests`. The Swift package (`Package.swift`) targets iOS 17 / macOS 14 with default localization `en`.
- **Signing / entitlements**: The app and `EiscueBroadcast` share App Group `group.org.eiscue.app` (`ScreenBroadcastStore.defaultAppGroupIdentifier`). The app and `EiscueTunnel` need the Network Extension `packet-tunnel-provider` capability. HID uses `org.eiscue.hid` / `.broadcast` with `group.org.eiscue.hid`, set through `EiscueScreenBroadcastAppGroup` on app and extension. If you change the app's bundle ID, keep the `.tunnel` / `.broadcast` suffixes and update the App Group to match.
- **Info.plist keys** are set in `project.yml`: camera, Bluetooth, microphone, speech and local-network usage strings (localized in `InfoPlist.xcstrings`); `UIBackgroundModes: bluetooth-central`; `BGTaskSchedulerPermittedIdentifiers`; `NSAllowsLocalNetworking`; and Bonjour `_remotepairing._tcp` / `_remotepairing-pairable-host._tcp`.
- **Dependencies** are pinned. PiDurableKit uses revision `6e7f2671…` (SwiftPM) and swift-markdown is exactly 0.9.0 (Xcode project only). The committed root `Package.resolved` also carries the Xcode-only swift-markdown / swift-cmark pins (there is no separate workspace lockfile); a plain `swift test` rewrites it without them, which is why the lockfile rule above exists. `Cargo.lock` and firmware `dependencies.lock` are committed. See `docs/architecture/dependencies.md`.
- **Environment variables**: `EISCUE_TEST_MODEL_URL` (UI-test model fixture), `EISCUE_RUST_TOOLCHAIN` (default `1.96.0`), `IDF_PATH` / `IDF_TOOLS_PATH` (ESP-IDF 5.5.3), `BOARD_SANITIZERS`, `BOARD_AUTH_OPENSSL_PREFIX` and `CC` (firmware host tests). Hardware UI cases also read `EISCUE_WAIT_FOR_SYSTEM_PAIRING`, `EISCUE_ATTACH_EXISTING_PAIRING` and `EISCUE_OPEN_PAIRING_SETTINGS` (pass with the `TEST_RUNNER_` prefix through `xcodebuild`).
- **Runtime data**: Everything lives in the app sandbox under `Application Support/Eiscue/`: `conversations.json`, `Runtime/` (per-conversation Pi SQLite), `Runs/` (task journal), `Skills/` (imported), and `Attachments/`. Built-in skills are `Apps/Eiscue/Resources/Skills/*.md`. Deleting a conversation removes its runtime files and journal; deleting the API key keeps conversations. Preferences such as `deviceConnectionMethod`, `deviceControlBackend`, `bluetoothInputRoute`, `allowsDeviceControl`, `disconnectAfterTask`, `appearance`, `modelProfiles` (profile list and selection; no keys), the legacy `modelSettings` projection and `onboardingVersion` are stored in UserDefaults. `Runs/`, `Runtime/` and the ReplayKit frame cache are excluded from backup; user conversations and original attachments keep their existing backup behavior. `conversations.json` v2 is a manifest; `conversations.json.store/` contains per-conversation records and SHA-256 content blobs under `blobs/`. Migration retains exact v1 bytes in `conversations.json.legacy-v1` until explicit conversation deletion retires the backup. Pending deletions must reconcile on load/before mutations; never allow an ID in both active and pending lists. New SQLite attachment metadata uses content descriptors; old metadata remains readable.
- **Local tunnel** addresses are fixed: local `10.7.1.1/24`, peer `10.7.0.1/32`, host route only, no default route or DNS. The USB NCM board is `192.168.7.1/24` and the phone uses a manual `.2`.
- **Build artifacts**: `.build/` is gitignored and holds research checkouts, backend/firmware builds, test results, and private board backups.
